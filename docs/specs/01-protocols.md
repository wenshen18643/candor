# 01 · Cryptographic protocols and wire formats

This file is the interoperability contract between the TypeScript client (`packages/crypto`,
libsodium-wrappers-sumo, @cloudflare/blindrsa-ts, shamir-secret-sharing) and Python (`PyNaCl`,
`cryptography`). Both sides MUST pass the shared vectors in `docs/specs/vectors/protocol-vectors.json`
(generated by `scripts/gen_protocol_vectors.py`).

## Encodings

- `b64u`: base64url, no padding. `hex`: lowercase.
- `utf8(s)`: UTF-8 bytes of `s`.
- `ctx(purpose, report_id)`: `utf8("candor/v1/" + purpose + "/" + report_id)`, used as AEAD
  associated data. Purposes: `manifest`, `file/<index>`, `analysis`, `findings`.
- Canonical JSON: `json.dumps(obj, sort_keys=True, separators=(",", ":"), ensure_ascii=False)`
  encoded UTF-8. Whenever a hash or signature covers JSON, the producer also transmits the exact
  bytes as b64u so verifiers never re-canonicalise.

## Padmé padding (PURBs, Nikitin et al. 2019)

Frame plaintext `P` as `F = u32be(len(P)) || P`. Let `L = len(F)` (always >= 4).
`E = floor(log2(L))`, `S = floor(log2(E)) + 1`, `z = E - S`, `padded_len = ceil(L / 2^z) * 2^z`.
Append `padded_len - L` zero bytes. Unframe by reading the u32 length prefix. Padmé leaks at most
O(log log M) bits of the length and has at most ~12% overhead.

## CandorBox (symmetric AEAD envelope)

```json
{ "v": 1, "alg": "xc20p-padme", "n": "<b64u 24-byte nonce>", "c": "<b64u ciphertext>" }
```

`c = crypto_aead_xchacha20poly1305_ietf_encrypt(padme(F), ad = ctx(...), nonce = n, key = K)`.
Keys are 32 random bytes. A fresh random nonce per box.

## SealBox (asymmetric, to an X25519 public key)

`b64u(crypto_box_seal(padme(F), recipient_pk))` wrapped as
`{ "v": 1, "alg": "seal-padme", "c": "<b64u>" }`. Key wraps (32-byte keys, Shamir shares) are sealed
WITHOUT Padmé framing and transmitted as a bare b64u string field named `sealed_*`.

## Keys

| Key | Type | Owner | Purpose |
| --- | --- | --- | --- |
| `K_r` report key | 32B symmetric | reporter browser, then quorum | encrypts manifest and files |
| `K_a` analysis key | 32B symmetric | reporter browser, worker | encrypts the redacted analysis payload |
| `K_f` findings key | 32B symmetric | worker, reviewers | encrypts the analysis result |
| reviewer `enc` | X25519 (`crypto_box_keypair`) | reviewer browser | receives sealed shares, findings keys, replies |
| reviewer `sig` | Ed25519 (`crypto_sign_keypair`) | reviewer browser | auth challenges, quorum approvals |
| enclave `enc` | X25519 | analysis worker (`CANDOR_ENCLAVE_SK`) | unseals `K_a` |
| inbox `enc`/`sig` | X25519 / Ed25519 derived from codename | reporter | anonymous two-way channel |
| issuer | RSA-2048, e=65537 | identity service, one per campaign | RFC 9474 blind token issuance |
| log | Ed25519 | API | signs tree heads |

`key_id` for X25519/Ed25519 keys: `hex(generichash(16, pk))` (BLAKE2b-128). For issuer keys:
first 16 hex chars of `sha256(spki_der)`.

## Threshold custody of the report key

`shares = split(K_r, n, k)` using `shamir-secret-sharing` (privy-io, GF(256)). Shares are opaque
byte strings. Each share is sealed to reviewer `i`'s `enc` key: `sealed_share_i`. Only browsers ever
combine shares. Python never parses shares.

Access flow: requester opens an access request. Each approver unseals its own share in the browser,
re-seals it to the requester's `enc` key (`resealed_share`) and signs
`utf8("candor/v1/approve\n" + request_id + "\n" + report_id + "\n" + requester_id)` with its `sig`
key. The API verifies the Ed25519 signature before storing. When `k` shares (the requester's own
plus `k-1` resealed) are available, the requester combines locally.

## Anonymous inbox keys from a diceware codename

- Codename: 8 words drawn uniformly (CSPRNG, rejection sampling) from the EFF large wordlist
  (7776 words), joined by `-`. About 103 bits of entropy.
- `normalize(c)`: lowercase, trim, replace any run of whitespace, `_` or `-` with a single `-`.
- `INBOX_SALT = generichash(16, utf8("candor/v1/inbox-salt"))`.
- `seed = crypto_pwhash(32, utf8(normalize(codename)), INBOX_SALT, opslimit = 3,
  memlimit = 67108864, alg = ARGON2ID13)`.
- `sign_seed = generichash(32, utf8("sign"), key = seed)`;
  `box_seed = generichash(32, utf8("box"), key = seed)`.
- `crypto_sign_seed_keypair(sign_seed)`, `crypto_box_seed_keypair(box_seed)`.

## Blind tokens (RFC 9474, RSABSSA-SHA384-PSS-Randomized)

1. Client: `msg = random(32)`; `prepared = prepare(msg)` (32-byte random prefix || msg).
2. Client: `{ blindedMsg, inv } = blind(issuer_pk, prepared)`; sends `blindedMsg` to identity service.
3. Identity service: `blindSig = blindSign(issuer_sk, blindedMsg)`.
4. Client: `signature = finalize(issuer_pk, prepared, blindSig, inv)`.
5. Token: `{ "key_id": "...", "prepared": b64u(prepared), "signature": b64u(signature) }`.
6. API verifies with standard RSASSA-PSS-VERIFY: SHA-384, MGF1-SHA-384, salt length 48, message
   `prepared`. Spent registry key: `hex(sha256(prepared))`. A token is valid only for the campaign
   whose issuer key verifies it.

Issuer public keys are distributed as SPKI DER, b64u.

## Merkle trees (RFC 9162 §2.1)

`leaf_hash(d) = SHA256(0x00 || d)`, `node_hash(l, r) = SHA256(0x01 || l || r)`. MTH of an empty
list is `SHA256("")`. For `n > 1`, split at `k` = largest power of two smaller than `n`. Inclusion
proofs (§2.1.3) and consistency proofs (§2.1.4) and their verification algorithms (§2.1.3.2,
§2.1.4.2) exactly as in the RFC.

- Evidence root: leaves are the raw 32-byte SHA-256 digests of each submitted file's bytes (after
  metadata stripping), ordered by file index.
- Transparency log: leaves are the canonical JSON bytes of each log entry.

## Signed tree head

```json
{ "tree_size": 42, "root_hash": "<hex>", "timestamp": "2026-10-26T10:00:00Z", "key_id": "<hex>", "signature": "<b64u>" }
```

Signature: Ed25519 over `utf8("candor/v1/sth\n" + tree_size + "\n" + root_hash + "\n" + timestamp)`.

## Reviewer and inbox authentication

- Reviewer: `POST /v1/auth/challenge {reviewer_id}` returns 32 random bytes `challenge` (b64u, 120 s
  TTL, single use). Client signs `utf8("candor/v1/auth\n" + reviewer_id + "\n" + challenge)`.
  `POST /v1/auth/token` returns an HS256 JWT (`sub` = reviewer_id, `org`, `role`, 8 h expiry).
- Inbox: same pattern with message `utf8("candor/v1/inbox-auth\n" + sig_pk_b64u + "\n" + challenge)`
  and a 30-minute token scoped to the reports bound to that `sig_pk`.

## Submission request

```json
{
  "report_id": "uuid",
  "campaign_id": "northwind-ethics",
  "token": { "key_id": "...", "prepared": "b64u", "signature": "b64u" },
  "evidence_root": "hex",
  "manifest": "CandorBox(K_r, ctx('manifest'))",
  "files": [{ "index": 0, "box": "CandorBox(K_r, ctx('file/0'))" }],
  "key_shares": {
    "scheme": "shamir-gf256",
    "threshold": 2,
    "shares": [{ "reviewer_id": "uuid", "sealed_share": "b64u" }]
  },
  "analysis": { "enclave_key_id": "hex", "sealed_key": "b64u", "box": "CandorBox(K_a, ctx('analysis'))" },
  "inbox": { "sig_pk": "b64u", "enc_pk": "b64u" }
}
```

Manifest plaintext:

```json
{
  "v": 1,
  "report_id": "uuid",
  "campaign_id": "...",
  "files": [
    {
      "index": 0, "name": "memo.pdf", "mime": "application/pdf", "size": 1234, "sha256": "hex",
      "variant": "original | redacted",
      "metadata_removed": [{ "field": "Author", "preview": "Pr***" }]
    }
  ],
  "pseudonym_map": [{ "placeholder": "PERSON_1", "type": "person", "value": "Dana Whitfield", "variants": ["Dana", "D. Whitfield"] }],
  "self_redaction_count": 7
}
```

The analysis plaintext is an `AnalysisPayload` (see 04-pipeline). It never contains real names,
contact details or the reporter's self-identifiers.

## Findings envelope (worker to API)

```json
{
  "box": "CandorBox(K_f, ctx('findings'))",
  "sealed_keys": [{ "reviewer_id": "uuid", "sealed_key": "b64u" }],
  "findings_sha256": "hex of canonical JSON plaintext"
}
```

## Messages

- Reviewer to reporter: `SealBox` of JSON `{ "kind": "question" | "message", "body": str,
  "questions": [{ "question_id", "text" }], "sent_at": iso }` to the inbox `enc_pk`.
- Reporter to reviewers: one `SealBox` per reviewer `enc_pk`, JSON `{ "kind": "reply", "body": str,
  "answers": [{ "question_id", "text" }], "sent_at": iso }`.

## Timing hygiene

Reporter-facing log entries carry hour-bucket timestamps (`2026-10-26T10:00:00Z`). The client waits a
random 2-20 s jitter before submission and may send same-sized chaff to `POST /v1/chaff`. Tokens are
valid for the campaign's 30-day epoch so verification and submission need not be adjacent.
